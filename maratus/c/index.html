§ 01  /  COUNTER DISPLAY

maratus counter display.
trigger-only.

Palm-sized touchscreen. Sits by the till, faces the customer. One POST from your system, one QR on the glass, one scan by the customer's phone.

Behind the code: your URL — receipt, ticket, warranty, menu. On screen: for a bounded moment, then idle. Paper: none.

PILOT SEQUENCE ↓

POST /trigger → QR → confirm → scan

§ 02

The object.

FORM
Palm-sized touchscreen. Counter-mounted, customer-facing.
FOOTPRINT
Occupies the receipt printer's footprint, not the till's.
IDLE
The organisation's own screen.
BRANDING
Layout and branding: set in the console, pushed org-wide to every claimed box in every store. Not settable per request — the trigger carries a URL and nothing else.
OUTPUT
Display only. No print path, no capture path, no delivery path.
HARDWARE
The screen. Reading is done by the customer's own phone.
RETENTION
What the customer receives is never read, printed, sent or retained by the device.

    CREDIT · HOLD

  3. 03

    CONFIRM

    Device confirms the display. Paid on show.

    settled

    CREDIT · SETTLED

  4. 04

    SCAN

    The customer's own phone. Free, terminal.

    unchanged

    CREDIT · SETTLED

NO DISPLAY → HOLD RELEASED → NO LATE CODE

No confirmation: the trigger expires, the hold is released, and a late code never appears. If the box cannot put the code on screen, the credit comes back.

§ 05

The request.

POST /api/v1/devices/{id}/trigger
Authorization: Bearer <api-key>
Idempotency-Key: <your-key>
Content-Type: application/json

{ "action": "show_qr", "payload": { "url": "https://your-shop.example/r/8f21" } }
202 { "id": "trg_...", "status": "queued" }
Documented responses
codemeaning
202queued, one credit on hold
401no or bad API key
403insufficient_scope — the key is not allowed to trigger this device
409device_offline — raised before any hold is taken
429too many requests
  • IDEMPOTENCY Idempotency-Key required — retry-safe, no double display.
  • TRANSPORT MQTT to the device. Device displays, device confirms, credit settles.
  • THE LINK The URL is passed through to the code verbatim; never fetched, never rendered — we never see what's behind the link.
  • DURABLE POST /api/v1/devices/{id}/pin — credit spent immediately, no hold.
  • REPORTING GET /api/v1/usage
  • NOT SHIPPED Status endpoint. Callback. The trigger is fire-and-confirm, one way.
